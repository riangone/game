各语言获取时间戳

下面是几种常用语言获取当前时间戳、以及把时间戳转回日期的写法。注意每种语言默认给出的单位不一样，混用时最容易出错。

语言当前秒级（10 位）当前毫秒级（13 位）时间戳 → 日期
JavaScript Math.floor(Date.now() / 1000) Date.now() new Date(sec * 1000) new Date(ms).toLocaleString('zh-CN', { timeZone: 'Asia/Shanghai' })
Python import time int(time.time()) time.time_ns() // 1_000_000 from datetime import datetime, timezone datetime.fromtimestamp(sec, tz=timezone.utc)
Java Instant.now().getEpochSecond() System.currentTimeMillis() Instant.ofEpochSecond(sec) .atZone(ZoneId.of("Asia/Shanghai"))
Go time.Now().Unix() time.Now().UnixMilli() time.Unix(sec, 0).UTC() time.UnixMilli(ms)
MySQL SELECT UNIX_TIMESTAMP(); SELECT FLOOR(UNIX_TIMESTAMP(NOW(3)) * 1000); SELECT FROM_UNIXTIME(sec);

说明：Python 的 time.time() 返回带小数的秒，取整后才是 10 位；Java 需要 import java.time.*；Go 的 UnixMilli 需要 Go 1.17 及以上；MySQL 的 FROM_UNIXTIME() 按当前会话的 time_zone 输出，服务器时区不是北京时间时结果会差几个小时。

常见问题

10 位和 13 位时间戳有什么区别？怎么判断是秒还是毫秒？

两者都是从 1970-01-01 00:00:00 UTC 起算的时长，只是单位不同：10 位是秒，13 位是毫秒，13 位的数值正好是 10 位的 1000 倍。Unix 命令、PHP、MySQL 的 UNIX_TIMESTAMP() 和 Python 的 time.time()（取整后）通常给出秒；JavaScript 的 Date.now() 和 Java 的 System.currentTimeMillis() 给出毫秒。看位数就能判断：2001 年 9 月到 2286 年 11 月之间的秒级时间戳都是 10 位，同期的毫秒级都是 13 位。本页会按位数自动识别，并在结果里注明识别成了哪一种。如果把毫秒当成秒去转换，会得到几万年以后的日期；反过来则会落在 1970 年 1 月附近，看到这类结果基本就是单位弄错了。

时间戳和时区有关吗？为什么同一个时间戳在北京和伦敦显示的时间不一样？

时间戳本身与时区无关，它表示的是全世界同一个瞬间，同一时刻在北京和伦敦取到的时间戳完全相同。不同的只是把它换算成“几点几分”时采用的时区：北京时间是 UTC+8，全年不实行夏令时；伦敦冬季是 UTC+0，夏令时期间是 UTC+1。所以同一个时间戳，北京显示的时间比伦敦早 8 小时（夏季为 7 小时）。存储和传输时建议一律用时间戳或带时区的 UTC 时间，只在展示给用户时再转成当地时间，这样跨时区的服务器和客户端就不会对不上。

什么是 2038 年问题？

很多老系统用 32 位有符号整数保存秒级时间戳，它能表示的最大值是 2147483647，对应 2038-01-19 03:14:07 UTC（北京时间同日 11:14:07）。再过一秒数值就会溢出变成负数，时间会被解释成 1901 年 12 月，可能导致排序、过期判断、证书校验等逻辑出错。现代操作系统和主流语言大多已改用 64 位整数，足够用到非常遥远的未来；需要留意的是嵌入式设备、旧的 C 程序、数据库里定义为 32 位 INT 的字段，以及 MySQL 的 TIMESTAMP 列类型，它的上限同样是 2038-01-19 03:14:07 UTC，新项目可以改用 DATETIME 或 BIGINT 保存。

时间戳可以是负数吗？

可以。负数表示 1970-01-01 00:00:00 UTC 之前的时刻，例如 -86400 就是 1969-12-31 00:00:00 UTC。JavaScript、Python、Java、Go 都支持负的时间戳，本页也可以直接输入负数转换。不过有些数据库函数和老系统只接受非负值，例如 MySQL 的 FROM_UNIXTIME() 遇到负数会返回 NULL，保存 1970 年以前的日期时建议直接用日期类型。
